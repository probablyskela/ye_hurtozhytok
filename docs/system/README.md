# Система

## Як це працює

```text
Телефон (PWA: manifest, service worker, пуші)
        │  HTML-форми + React (гідратація)
        ▼
Cloudflare Worker ── React Router v7 (loaders / actions, SSR)
        │  Drizzle ORM          │ Cron Trigger щохвилини
        ▼                       ▼
Cloudflare D1 (SQLite)    нагадування: Web Push, запасний канал — лист
        ▲
Google (OpenID Connect) ── вхід лише для акаунтів @lpnu.ua
```

Один Worker віддає сторінки й обробляє форми, окремого API немає: кожен
маршрут має `loader` (читання) і `action` (зміни). Форми працюють і без
JavaScript. Стек і підходи ті самі, що в Опереті.

## Структура коду

```text
apps/web/app
  routes/               маршрути: loader читає, action змінює
  lib/booking.ts        правила запису (чисті функції, тести)
  lib/bookings.server.ts записи в D1, запис без гонок
  lib/auth.server.ts    сесії, вхід через Google, локальний вхід
  lib/google.ts         перевірка токена Google (домен lpnu.ua)
  lib/webpush.ts        Web Push без бібліотек (VAPID, aes128gcm)
  lib/scheduled.server.ts нагадування щохвилини
  lib/db/schema.ts      таблиці Drizzle
  components/           спільні елементи інтерфейсу
apps/web/public         sw.js, manifest, іконки
apps/gateway            Pages-шлюз для адреси ehurtozhytok.pages.dev
infra/d1/migrations     міграції, генеруються з db/schema.ts
```

Наступні частини (оголошення, дошка студради, оплата) — нові маршрути й модулі в `lib/`.

### Час

Запис зберігає київську календарну дату `date` (`YYYY-MM-DD`) і хвилини від
півночі за Києвом `start_min`, `end_min`. Тому «18:00» лишається 18:00 і після
переходу на літній час. UTC обчислюється з цього лише для нагадувань, через
`lib/time.ts`. Запис не переходить через північ. Моменти подій (створено,
скасовано) — UTC у мілісекундах, як в Опереті.

### Статуси запису

`active` або `cancelled`. Чи запис уже минув, видно з часу, окремо не
зберігається. «Звільнити раніше» переносить `end_min` на найближчі наступні
5 хвилин від зараз.

Під оплату згодом додається статус `held` з `expires_at`: запис тримається
кілька хвилин, поки людина платить, а вебхук еквайрингу переводить його в
`active`. Тоді ж з’явиться таблиця `payments`.

## Запис і перевірка вільного часу

Правила (`apps/web/app/lib/booking.ts`, чисті функції з тестами; числа — константи там же):

- початок кратний 5 хв; тривалість від 30 хв до 2 год 30 хв з кроком 30 хв;
- запис уміщується в години роботи (06:00–24:00) й не переходить через північ;
- між записами на одній пралці щонайменше 5 хв запасу;
- не більше 3 незавершених записів на людину; дата — від сьогодні до 7 днів.

**Вільні початки.** Для пралки й дня беремо активні записи, розширюємо кожен
на запас з обох боків і перебираємо початки з кроком 5 хв: підходить той, з
якого `[start, start + тривалість)` не перетинається з жодним розширеним
записом. Сьогодні — лише початки не раніше поточного кроку.

**Запис без гонок.** Перевірка й вставка — одна SQL-інструкція, тому двоє
людей не займуть той самий час навіть одночасно (D1 виконує записи послідовно):

```sql
INSERT INTO bookings (machine_id, resident_id, date, start_min, end_min, status, created_at)
SELECT :machine, :resident, :date, :start, :end, 'active', :now
WHERE NOT EXISTS (
  SELECT 1 FROM bookings
  WHERE machine_id = :machine AND date = :date AND status = 'active'
    AND start_min < :end + :buffer AND end_min + :buffer > :start
)
AND (SELECT count(*) FROM bookings
     WHERE resident_id = :resident AND status = 'active'
       AND (date > :today OR (date = :today AND end_min > :now_min))) < :limit;
```

Якщо вставлено 0 рядків, сервер з’ясовує причину (час зайняли чи вичерпано
ліміт) і показує її людині.

## Вхід через пошту Політехніки

Пошта @lpnu.ua працює на Google Workspace, тому вхід — стандартний OpenID
Connect від Google (authorization code + PKCE), без паролів у нас:

1. `POST /auth/google` створює `state`, `nonce` і `code_verifier`, кладе їх у
   підписане httpOnly cookie на 10 хвилин і перенаправляє на Google з
   `hd=lpnu.ua`, `scope=openid email profile`.
2. `GET /auth/callback` звіряє `state`, обмінює код на `id_token` і перевіряє
   його підпис (JWKS Google), `aud`, `iss`, `exp`, `nonce`, а головне —
   `hd === "lpnu.ua"` і `email_verified`. Параметр `hd` у запиті лише підказка
   для екрана Google, тому перевірка на сервері обов’язкова.
3. Мешканця шукаємо за `sub` (стабільний ідентифікатор Google), ім’я й пошту
   оновлюємо при кожному вході. Новий мешканець вказує кімнату й, за бажанням,
   ім’я користувача в Telegram.

Сесія — підписане cookie на рік з `resident_id` і `session_version`;
блокування збільшує `session_version`. Вхід, розпочатий у встановленій PWA на
iPhone, повертається в неї ж: перенаправлення в межах того самого вікна.

Ризик: адміністратор Google Workspace університету може заборонити стороннім
застосункам вхід через акаунти @lpnu.ua. Перевірити до запуску; запасний план —
одноразовий код на пошту @lpnu.ua через Cloudflare Email Sending.

Вхід підтверджує, що людина з Політехніки, але не що вона живе саме в
гуртожитку №14. Це свідомий компроміс: ліміт записів обмежує шкоду, студрада
може заблокувати людину.

## Сповіщення

- Cron Trigger щохвилини (`* * * * *`) шукає записи, що починаються в
  найближчі 15 хв і ще не мають `reminded_at`, надсилає нагадування і ставить
  позначку, щоб не надіслати двічі.
- **Web Push**: ключі VAPID, шифрування повідомлень (RFC 8291) через WebCrypto
  прямо у Worker. На iPhone пуші працюють лише у встановленій PWA (iOS 16.4+),
  тому застосунок показує інструкцію «Додати на початковий екран».
- **Лист** на адресу @lpnu.ua через Cloudflare Email Sending — для тих, у кого
  немає пуш-підписки. Помилки відправки лише логуються й не ламають дію, як в
  Опереті (`ctx.waitUntil`).

## Захист

- Підписки на пуші приймаються лише від сервісів браузерів (Google, Mozilla,
  Apple, Microsoft) і не більше 5 пристроїв на людину: сервер ніколи не шле
  запитів на довільні адреси.
- Дата, пралка, початок і тривалість запису перевіряються суворо ще до SQL.
- Нагадування спершу «займаються» одним `UPDATE … WHERE reminded_at IS NULL
RETURNING`, тож навіть два одночасні запуски cron не надішлють його двічі.
- Вихід видаляє підписку цього пристрою на пуші й кеш сторінок (заголовок
  `Clear-Site-Data` і очищення в браузері). Service worker зберігає для офлайну
  лише головну й сторінки пралок, ніколи — профіль, записи чи студраду.
- Заблокований мешканець може увійти й бачити профіль, але не записуватися;
  його ще не почати записи скасовуються в момент блокування.

## PWA

- `manifest.webmanifest`, іконки, `display: standalone`, світла тема.
- Власний невеликий `public/sw.js` (без `vite-plugin-pwa`, який погано
  поєднується з режимом фреймворку React Router): статичні файли — з кешу,
  сторінки — спершу мережа, без мережі — остання збережена версія з позначкою
  «станом на 14:20».
- Записатися чи скасувати без мережі не можна: це завжди запит до сервера.
- Розклад оновлюється опитуванням раз на 20 с, поки вкладка видима.
- QR-наліпка на кожній пралці веде на її сторінку.

## Права

Усі перевірки — у `lib/permissions.ts`, кожна дія перевіряє їх на сервері.
Ролі: `resident` і `council`. Студрада скасовує будь-які записи (на сторінці
пралки) й блокує людей (`/council`). Члена студради призначає скрипт
`npm run council:add -- --email імʼя@lpnu.ua [--remote]`.
